# Stage 1 dangers

These sequences are derived only from the specification and dispatch. No product code, supplied checks, or other seat's tests were read. Unit references name the independent sentence ledger. The five ambiguous units require foreman rulings before their final audit assertions are fixed.

1. **Old completion after replacement.** Hold a first build's provider response; reset to a disjoint fixture; create the same normalized domain again; release the old response. The old build must not install fields, spending, credentials, or replay records into the new state. Repeat using import rather than reset: replacement must be atomic and discard destination work, not merely its visible rows. Units S1-070–074, S1-293–306, S1-311–312.
2. **Same domain, different writers and keys.** Race 50 create requests across two users and case/www/trailing-dot variants, with distinct keys and some identical keys. There must be one dossier and one build. Same-key duplicates return the original response with 200; different users' identical keys do not interact. Race refresh against completion and another refresh: at most one active build at any instant. Units S1-095, S1-098–102, S1-195–210, S1-220, S1-233–235, S1-253, S1-311.
3. **Claim resolution after a lost response.** Create successfully but discard the response; change clock; let the build finish; retry with reordered JSON and changed unknown fields. Return the original building response with 200 and no new call. Change the known domain to an invalid string, null, or another wrong type in a parsed object: the existing claim wins with 409. An unparseable body is a distinct earlier parse failure. Use the same key on a different raw refresh path and under a different user to confirm independent scopes. Units S1-184, S1-197–214, S1-228.
4. **A failed request must not poison the key.** Refresh an absent domain, then create it and reuse the failed refresh key. Repeat after export/import. Try an invalid create first, then a valid create under its key. Each first 4xx leaves the key reusable; no export can silently turn failure into a completed claim. Units S1-204, S1-255, S1-300, S1-303–304.
5. **Refresh failure and stale presentation.** Build supported fields at clock T1; refresh at T2 with all calls refused; read/list during and after the failed refresh; replay the original create and refresh requests. Fields and researched_at stay at the last ready result, state becomes failed, spending follows actual error rules, and replay bodies remain their historical JSON values. Then refresh successfully with different evidence: all six fields replace together, including removal of previously known fields whose support disappeared. Units S1-211–223, S1-240–245, S1-254, S1-259, S1-311–312.
6. **Clock advances while providers wait.** Begin a delayed build at T1; set clock to T2 before it completes. Its researched_at must be T1. Two builds without clock changes receive the same time despite wall-time passage. Reject a backwards clock request without changing any state; reset may set an earlier fixture time. Test equivalent instants with different offsets. Pre-reset behavior follows the S1-080 ruling. Units S1-076–087, S1-147, S1-219, S1-244.
7. **A real cross-process transfer.** Populate source with seeded and signed-up users, several valid tokens, ready and failed dossiers, citations, cumulative spending, successful create/refresh keys, and failed reusable keys. Export privately; destroy the source container; import unchanged bytes into a separately started container with different port and disjoint existing data. Original ids/timestamps/hashes/tokens/retries must work; previous destination credentials must stop working; no provider call occurs. Reimport after further destination writes, then reset. The destination clock stays its own clock throughout export/import. Units S1-287–307.
8. **Transfer during the first build and during refresh.** Hold replies after spending is incurred, export, allow the source to finish, and import the saved object elsewhere. A first-build snapshot imports failed/all-unknown; a refresh snapshot imports the last completed state and fields. No background work resumes on import. Resolve the snapshot spending rule under S1-309 before asserting its exact expected number. Preserve completed idempotency responses even when they say building and the restored dossier is terminal. Units S1-202, S1-245, S1-299–309.
9. **Failed replacement is wholly inert.** With active sessions, ready dossiers, clock T, and completed keys, submit duplicate-email reset fixtures and invalid imports: missing fields, wrong track/version, structurally invalid state, malformed JSON. Every rejection must preserve all prior data, passwords/tokens, clock, and retry behavior. Concurrent reads must never see partially replaced state. Units S1-083, S1-149, S1-156–166, S1-297, S1-311–312.
10. **A cheaper answer can be incomplete.** Put some fields only in full text beyond a snippet, only on a second company-naming query, and only in an all-six-field research answer. Initial exact-domain results can be incomplete or misleading; Facts headers can point to unsupported values. A build must satisfy the S1-121/S1-223 evidence ruling without exceeding its 80-unit budget. Research claims require supporting cited prose, not trust in the claimed value. Units S1-012–014, S1-121–143, S1-223, S1-284–285.
11. **Exact-domain retries and total failure.** Refuse the first exact-domain search, then permit one; error searches do not count, and the build must not accidentally perform two successful exact-domain searches. Refuse every provider call and verify bounded failed completion under the S1-122 ruling. Do not turn a provider exception into an API 5xx. Units S1-122–123, S1-171, S1-221, S1-224–227, S1-280–284.
12. **Reserve before parallel calls, not after responses.** Arrange enough missing fields/pages to approach 80 units; hold several calls; introduce timeouts, connection loss, provider refusals, and missing-page extracts. Account for every requested extract URL, including absent pages, and charge uncertain delivery normally. Rejected calls cost zero except no-page extract responses. Concurrent reservations must not overshoot; failed/refreshed builds still contribute cumulative cost. Units S1-014, S1-245, S1-269–284. Dispatch also requires planning searches once per build and reusing text already served within that build; a refresh calls again.
13. **Support cannot leak across contexts.** Put a company name in one sentence, a field phrase in another, and the value in a third. Put plausible metadata only in Facts headers. Put another company's facts on a page about the target. Include an unsupported research claim with a real but irrelevant citation. None can manufacture a known value, even when the prose is semantically suggestive. Units S1-126–143, S1-314–332.
14. **One sentence, several candidate values.** Include two CEO names, two distinct founding years, same-bucket versus cross-bucket headcount ranges, and repeated funding amounts with equal versus unequal normalized dollars. A sentence supports a field only if every formally matching value normalizes to one value. Distinct supporting sentences may conflict, but the chosen value's citations must all support that same value. Amount-contained digits must not leak into year/headcount matching. Units S1-112, S1-135, S1-330, S1-358–379.
15. **The grammar matters more than a plausible reading.** Test all negators and all statement phrases with mixed case and boundary near misses. Test Unicode capitalised words, two/three/four-word person runs, hyphenated cities, dotted suffixes, shortest overlapping legal-name matches, number grouping, and decimal-dollar integrality. A longer title-case run must not yield a permitted shorter CEO/city substring. A legal suffix period must not split a sentence. A citation must remain a provider-served prose span of 1–500 characters. Units S1-126–128, S1-317–379.
16. **Read traffic must stay free.** After a build is idle, issue 50-way get/list/health/auth/clock/export/import traffic. Provider counters must not advance. While a build is active, control for that build's expected calls so unrelated endpoints are not credited with initiating research. List pagination must filter first, sort by domain, preserve null names, and calculate has_more at empty/beyond-end boundaries. Units S1-054, S1-067, S1-228, S1-258–266, S1-302.
17. **Boundaries and precedence.** Exercise label lengths 1/63/64, domain totals 253/254, one versus two labels, one versus repeated www prefixes/trailing dots, key lengths 0/1/255/256, name lengths 0/1/100/101, password lengths 7/8, limit 0/1/200/201, offset 0/positive/negative, digit-only versus exponent/decimal/plus query spellings. Wrong known-body types are 400, correct-type invalid formats are 422, unknown fields are ignored, and invalid authentication precedes missing keys. Units S1-088–102, S1-156–184, S1-213–214.
18. **A clean isolated image is the product.** Follow RUN.md from a clean checkout with nondefault PORT, 2 vCPU, 3 GiB, no Compose or host source/volume, and runtime access only to configured local provider endpoints. Omit Tavily entirely and complete research through Nimble. Health must appear within 60 seconds, HTTP requests remain bounded, and async builds finish within the specified provider-dependent bounds. Only after black-box probes inspect manifest, WebRouter routing, dependency installation, password hashing, runtime assets, and live-provider timeout handling where externally unobservable. Units S1-017–067, S1-188–189, S1-224–228.
