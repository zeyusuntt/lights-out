# Stage 2 dangers

Derived independently from the opened Stage 2 specification, inherited Stage 1 requirements and rulings. No Stage 2 product code, product tests, supplied check sources or other seat's tests were read. Stage 1 is accepted and its product folder is final.

1. **A selected answer is not the whole dossier.** Give six fields plausible initial values, then put a higher-authority competing value on a later result or research-cited non-searchable page. The build must gather the required candidates even after every field already has some value, rank all candidates, retain disagreement, and expose only the selected value's citations. Early all-known stopping is no longer sufficient. Units S2-005, S2-054–080, S2-083–088. Inherited 80-unit relief applies when the next needed call cannot be afforded; leftover units below that call's price are not permission to invent or omit already obtained evidence.
2. **An unsupported research claim can lead to useful evidence.** Research claims a CEO using an irrelevant or negated citation on a non-searchable page. That claim is rejected, but the page has a valid founding year or another CEO elsewhere. Read its whole loaded text and collect those page-derived candidates. Do not skip the page merely because the claim is unsupported, or treat the claim's bare citation as the whole page. Units S2-055–057 and inherited support rules.
3. **Every value per page, once.** On one page put two valid sentences with different values, plus several repetitions of one value. On another page repeat that first value. The result is one candidate per page/value, not one per excerpt, and every distinct supported value remains. Many same-value candidates produce known, not contested; a single lower-authority conflicting candidate produces contested even when it cannot win. Units S2-053–068, S2-078, S2-083–086.
4. **Browser text replaces raw-source inference.** Put a plausible value only in hidden/script/source text and a different supported value in the loaded visible text. Obtain no-click browser text, reject source-only assertions, and keep provenance tied to the provider that actually served the cited visible text. No disclosure click is required. Check initial versus loaded text, not only simple static pages. Units S2-016–028, S2-060; Nimble alone must still suffice.
5. **Metadata is evidence, not URL guesswork when explicit.** Serve explicit own/filing headers on external hosts; omit or invalidate kind on normalized www/case/trailing-dot own hosts and subdomains; include valid/invalid/missing publication times. Exact valid headers win. Otherwise only the normalized host equal to the company is own. Invalid dates become null, not current time, parsed partial dates or fatal build errors. Units S2-011–014, S2-061–062.
6. **Ranking crosses several tie boundaries.** Put an old own candidate against newer news, equal-authority own and filing against each other, equivalent publication instants with different offsets, undated candidates, Unicode/case-different URLs, equal-URL provider ties and numeric 9 versus 10. Preserve the whole rank order; select exactly one candidate; include every winning-value citation in that same order. Provider arrival order, majority vote, locale collation and stringified integer comparison cannot alter the fixed rule. Units S2-008, S2-064–080.
7. **R1-7 applies to every candidate, not just the winner.** Give losing candidates short negated/competing-value sentences, long sentences with late supporting spans, amounts and capitalized-name runs near span edges. Every retained candidate and selected citation must have a valid served prose excerpt, length 1–500 and support under the whole-short-sentence/safe-long-span rulings. An invalid losing candidate can still falsely create contested status. Units S2-019–020, S2-053–060, S2-083–086 and inherited R1-6/R1-7.
8. **Throttling changes time accounting, not the spending cap.** Apply independent 429 sequences to exact-domain search, other searches, research, extracts and optional browser calls. Retry the same arguments, charge refusals zero, and count successful/uncertain calls normally with reservation before each call. Subtract real retry-wait periods from the fast-provider build bound. Do not give up after three refusals when a compliant next call can succeed. The cooldown/three-refusal interaction is S2-050's ruling question. Units S2-038–051 and inherited S1-122, S1-224, S1-280–284.
9. **Optional session limits under concurrent builds.** If using browser vendors, run several dossier builds while four sessions are open, close/release some, and handle provider closure after a clientless minute. A fifth open may be refused and consumes no units. Reuse/close owned resources so the session cap does not become an unbounded leak. Browser vendors remain optional; Nimble-only research must work. Units S2-026–045, S2-050 and inherited resource/concurrency rules.
10. **Refresh is atomic candidate replacement.** Build contested candidates at T1. Refresh at T2 while retaining T1 fields/candidates on reads; fail the refresh and keep the previous ready candidate set. Succeed later with fewer/different pages and replace the whole set, selected flags, status, citations and retrieved_at together. Do not accumulate stale candidates or replace metadata piecemeal. Units S2-063–065, S2-078–088, S2-188 and inherited build/reset/import concurrency.
11. **Direct navigation and content negotiation.** Visit every route without prior client navigation, including normalization variants. Request the shared dossier path with HTML Accept versus JSON API headers. Authentication must follow the S2-090/S2-100 ruling without breaking signed-out signup/login or protected API data. Routes and test identifiers cannot work only after starting at the home page. Units S2-090–103.
12. **UI summaries must follow selected data.** Change a selected legal name or winner through refresh/import. The dossier's human-formatted value, canonical data-value, list legal name, case-insensitive search results, candidate selected flags/citation order and cross-dossier contested membership must agree. Exactly one candidate is selected even when several share its value. Units S2-064, S2-078, S2-087–088, S2-131–162.
13. **Another client creates the domain after the list was read.** Keep an old browser list, create the dossier externally, then submit the browser's research form with a variant domain. The 200 success opens the existing normalized dossier, starts no build, and clears previous error/uncertainty feedback. Units S2-128–136 and inherited same-domain/idempotency rules.
14. **Latest read wins across manual reload and polling.** Hold one dossier GET. Let another client change state; issue and complete a newer reload or poll; then release the old response. The older data cannot overwrite newer fields/state/spending, resurrect building, or restart obsolete polling. Continue polling at least every two seconds while the current dossier is building, then stop the required polling at ready/failed. Units S2-151, S2-154, S2-168–172.
15. **Unknown writes are not refusals.** Lose a create or refresh response both before and after commit. Show only the matching nonempty uncertainty state and retain the exact original key/body for retry. Re-render, poll, and retry; a successful retry clears both feedback elements, displays the dossier and causes at most one build total. Separate confirmed 4xx refusal from a missing response. Do not silently mint a new key while the original outcome is unresolved. Units S2-129–130, S2-149–150, S2-173–176.
16. **Imported evidence may disagree with the legacy winner.** In the accepted Stage 1 service, gather conflicting values and same-value pages; finish ready; then perform a failed or in-progress refresh. Export privately and import unchanged into Stage 2. Reconstruct candidates from the last ready build's served text only, preserving researched_at as retrieved_at; recompute selection/status/citations, allowing a different selected value and contested status. Preserve account hashes, old tokens and original successful keyed responses; replace destination state and keep its clock unchanged. Units S2-179–185 and inherited S1-300–309.
17. **Migration information gap must be checked explicitly.** S2-182 requires every value supported by all text served to the last ready Stage 1 build, including unselected evidence. Stage 1's export contract explicitly preserved selected fields/citations but did not explicitly require retention of every page's served text. The accepted Stage 1 folder cannot be changed. During audit inspect an actual unchanged legacy export and its provider transcript; if the export lacks necessary text, that is a concrete information gap to raise to the foreman. The specification supplies no selected-citations-only fallback, and import still may not call providers. This is a risk identified from the contracts, not a claim about product code (none was read for this reading).
18. **A live browser survives replacement without reauthentication.** Keep the browser signed in using a token included in the legacy export; lose a committed write response; complete import between requests; retry from the existing screen. Recover the original response with the same key/body, show the imported dossier, and require neither a manual reload nor a new login/tab. The exact pre-upgrade UI setup is S2-180's ruling question because Stage 1 required only HTTP API behavior. Units S2-180–187.
19. **Imported null metadata remains truthful.** An old candidate with unrecorded kind/publication receives null, uses aggregator authority, retains original provider/excerpt/time, and is not assigned invented current metadata. Its next ready refresh replaces imported candidates with freshly gathered kinds/times. The evidence DOM must expose required attributes without making raw JSON the only way to understand metadata. Units S2-062–063, S2-157, S2-183–188.
20. **Product behavior and presentation are both required.** Walk signed-out/signed-in signup/login/logout, empty/search/research/ready/failed/contested/evidence and retry flows at 375px and desktop. Inspect clear value/status hierarchy with adjacent quoted source links, visible labels, keyboard focus, contrast, consistent navigation and coherent feedback. Technical testids/data attributes must not replace human-readable UI, and mobile must not scroll horizontally. Units S2-106–117 and S2-120–162. Product-user journey evidence will supplement independent browser probes, not substitute for missing behavioral evidence.
21. **Zero is a known value.** Serve a supported total funding of zero dollars. It must have a candidate, known status, a visible field-value element, human-formatted money, and data-value="0" on field/candidate/contested rows when applicable. Null checks cannot become generic truthiness checks. Change the candidate set to contest zero against a positive amount and confirm rank/status/citations and UI agree. Units S2-068, S2-076–086, S2-143, S2-153, S2-157, S2-161.

## Inherited audit boundary

All accepted Stage 1 requirements and rulings remain except explicit Stage 2 changes: candidates/contested selection replace the former one-value choice/status rule; browser-visible text governs evidence; rendered extract is now permitted and has its new price; additional optional providers/rate behavior apply. Reset, clock, idempotency, bearer-token API behavior, error taxonomy, container isolation/resource limits, privacy, export/import replacement and concurrency must still be checked on the exact Stage 2 candidate. The HTTP-versus-browser authentication interaction is explicitly left for the foreman ruling, not silently assumed.

This is the independent reading, not an audit or PASS. No Stage 3/4 specification was read. Stage 2 probes remain private until all stages close.
